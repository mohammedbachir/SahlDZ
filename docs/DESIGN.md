# SahlDZ Web Design System

## الشخصية

**SahlDZ Administrative Ledger**: نظام ERP عربي مكتبي هادئ وعملي، يشبه برنامج إدارة ومحاسبة موثوقًا للمدير العام. الدقة أهم من الإبهار، والمعلومة أهم من الزخرفة. لا يستعمل مفردات أو رموزًا أو مؤثرات توحي بمنتج AI، ولا يقلّد واجهات SaaS الحديثة شديدة النعومة.

> **V4:** الاسم البصري للتجربة هو **Restaurant Control Desk**. يحافظ على الطابع الإداري المكتبي في الطباعة والأدوات والجداول، لكنه لا يحافظ على هندسة ERP التقليدية ذات الشريط الجانبي. هذه واجهة جديدة لا نسخة محسنة من أي لقطة سابقة.

## مبادئ الواجهة

1. **القرار قبل العرض:** تعرض لوحة المدير الملخص المالي والتنبيهات أولًا، ثم التفاصيل القابلة للتنفيذ.
2. **اللون معنى:** النحاسي للهوية والفعل الرئيسي فقط؛ الأخضر للنجاح/الربح/التوفر؛ البرتقالي للتنبيه؛ الأحمر للخطر أو الحذف؛ الأزرق لمعلومة محايدة فقط.
3. **البيانات قبل البطاقات:** لا تحوّل كل معلومة إلى بطاقة. تستعمل الجداول للحركات والموردين والرواتب والمخزون، والبطاقات لملخصات قليلة فقط.
4. **هدوء بصري:** لا gradients، glassmorphism، neon، blobs ضبابية، 3D/tilt، أو hover-lift. انتقال اللون والحد فقط عند الحاجة.
5. **RTL أصيل:** المحاذاة، ترتيب الأفعال، مواضع الأيقونات، والأرقام تخدم العربية. الأرقام المالية تستخدم `tabular-nums` و`dir=ltr` عند الحاجة لمنع التباس القراءة.
6. **مكتبي مألوف:** الكثافة معتدلة إلى عالية؛ شريط أدوات وتبويبات ولوحات محددة وجداول، بدل مساحات كبيرة وبطاقات تسويقية.
7. **اختلاف بنيوي:** لا تعِد استخدام مخطط الصفحة القديم مهما تحسن شكله. إعادة ترتيب المحتوى وتغيير نوع مكوّن العرض مطلوبان.

## الخط والمسافات

- استخدم `Tahoma`, `Arial`، ثم خط عربي احتياطي متاح. لا تستخدم خط عرضي أو عناوين ضخمة لإضفاء طابع تسويقي.
- العنوان الرئيس: 18–20px؛ عنوان القسم: 15–16px؛ النص: 13–14px؛ الوصف/الجدول: 12–13px.
- استخدم سلم مسافات 4، 8، 12، 16، 24، 32px.
- نصف القطر: 4–6px للمتحكمات، و8px كحد أعلى للأسطح؛ لا تستخدم 20–32px بصورة افتراضية.
- الظل: لا ظل في الأسطح العادية؛ ظل صغير جدًا للحوارات والقوائم العائمة فقط.

## المكونات

### الأزرار

- رئيسي: نحاسي ممتلئ، نص أبيض، ارتفاع 34–36px افتراضيًا، أيقونة اختيارية قبل النص وفق RTL.
- ثانوي: أبيض بحد هادئ ونص فحمي؛ لا يتحول إلى نحاسي ممتلئ عند hover.
- شفاف: للأفعال الثانوية داخل الصفوف أو الشريط.
- خطر: أحمر للحذف والتأكيدات غير القابلة للعكس فقط.
- أيقونة منفردة: 36×36px، مع `aria-label` وtooltip عند عدم وضوح الفعل.

### التنقل

- شريط جانبي أيمن ثابت على الكمبيوتر بعرض واضح ويفصله خط واحد عن المحتوى؛ ليس بطاقة عائمة ذات ظل.
- قسّم العناصر إلى: نظرة عامة، تشغيل، ماليات، موارد، تقارير، إعدادات.
- أضف عنوانًا صغيرًا ومحايدًا لكل مجموعة.
- العنصر النشط فقط له خط نحاسي رفيع على الحافة اليمنى وخلفية نحاسية شاحبة + نص وأيقونة نحاسيان؛ بقية العناصر محايدة.
- أعلى الشريط: اسم SahlDZ/المطعم. أسفله: رابط الحساب وتسجيل الخروج منفصلان.

### رأس الصفحة وشريط الأدوات

- الرأس العلوي ضيق، وظيفي، وغير مزخرف: اسم المطعم، الفرع عند توفره، الفترة، الإشعارات، والحساب.
- داخل الصفحة: عنوان موجز، ثم شريط أدوات موحد للبحث، التصفية، نطاق التاريخ، التصدير، والإجراء الأساسي.
- تستخدم التبويبات للآراء المتجاورة في نفس المورد بدل إطلاق بطاقات انتقال متكررة.

### البطاقات والملخصات

- السطح أبيض وحد هادئ؛ لا زجاجية ولا أيقونة ضخمة داخل مربع ملون.
- في لوحة المدير، استعمل شريطًا ماليًا أفقيًا أو لوحة واحدة مقسمة: الإيراد، المصاريف، صافي الربح، والرصيد/المؤشر التشغيلي عند توفره.
- الإيراد وصافي الربح أكبر بصريًا من المقاييس الثانوية، مع وصف فترة واضح ومقارنة صغيرة عندما تتوفر بياناتها.
- لا تعرض أيقونات كبيرة داخل مربعات ملونة كتزيين؛ تستعمل الأيقونة الصغيرة فقط إن أضافت معنى تشغيليًا.

### الجداول

- رأس جدول بلون سطح ثانوي خفيف، صفوف بارتفاع مريح، حدود أفقية فقط، وhover محايد.
- شريط أدوات موحد أعلى الجدول: بحث، نطاق تاريخ، فلاتر، ثم التصدير/إضافة في الطرف المناسب لـ RTL.
- الحالات شارات نصية صغيرة لا ألوان خلفية قوية؛ لا لون مختلف لكل صف.
- على الجوال: إخفاء الأعمدة الثانوية أو عرض بطاقة بيانات مضغوطة، لا ضغط جدول عريض بلا حل.

### لوحة التحكم

1. رأس الصفحة: عنوان، نطاق التاريخ/الفرع عند توفره، وإجراء رئيسي واحد.
2. شريط مالي أفقي: الإيراد، المصاريف، صافي الربح، ومؤشر تشغيلي واحد فقط عند توفره.
3. «يتطلب انتباهك»: قائمة قصيرة قابلة للنقر، تسمّي المشكلة والفعل بوضوح، مثل «3 مكونات دون حد الأمان — فتح المخزون».
4. الأداء: رسم واحد بسيط قابل للقراءة يجاوره ملخص/جدول، بدل مجموعة مخططات متنافسة.
5. حركة حديثة: جدول آخر مشتريات أو عمليات أو تقارير؛ لا تترك أسفل الشاشة فارغًا.
6. الحالة الفارغة: نص يشرح غياب البيانات وإجراء مباشر، لا رسم توضيحي أو عناصر لطيفة بلا وظيفة.

### مخطط صفحة المدير V4 الإلزامي

```text
شريط أوامر علوي، صف 1: العلامة | المطعم والفرع | بحث | الفترة | الإشعارات | الحساب
شريط وحدات، صف 2: المتابعة | التشغيل | الماليات | الموارد | التقارير | النظام

لوحة يوم العمل (شبكة غير متناظرة، لا صفوف بطاقات):
  1. طابور العمل: إجراءات وتنبيهات حقيقية، كل عنصر يقود إلى عمل محدد
  2. موجز الأداء: أرقام مالية وتشغيلية متصلة في قراءة واحدة، بلا بطاقات KPI منفصلة
  3. النشاط الحديث: سجل زمني/جدول معاملات أو حالة فارغة عملية
  4. مساحة سياقية اختيارية تعتمد على بيانات موجودة فقط، مثل تقرير مختصر أو قائمة متابعة
```

لا تعرض بانر تنزيل التطبيق أو أي محتوى ترويجي في `/ops`. انقل هذا النوع من الوصول إلى الحساب أو الإعدادات إن كان مطلوبًا.

### قواعد الاستبدال الكامل

- لا شريط جانبي دائم، ولا تعويض له بشريط جانبي مختلف الألوان أو أضيق.
- لا شبكة cards أو صف KPI، حتى لو كانت البطاقات مربعة أو متصلة.
- لا تعيد توزيع مناطق الواجهة القديمة بترتيب جديد فقط؛ أنشئ DOM/layout جديدين لمنطقة العمل.
- لا تستعمل `OpsOverview` القديم كمكوّن حاوية؛ أعد كتابته كمشهد صفحة جديد مع الاحتفاظ بمنطق البيانات الضروري فقط.
- لا تضف بيانات مصطنعة لإكمال التصميم؛ حالة عدم وجود البيانات جزء من الواجهة الجديدة.

### هندسة التنقل V4 المعتمدة

| المجموعة | عناصرها الحالية |
| --- | --- |
| المتابعة اليومية | نظرة عامة |
| التشغيل | المخزون، جرد المخزون، الوصفات، المنيو والأصناف |
| الماليات | المصاريف، المحاسبة |
| الموارد | الموردون، الموظفون، أداء الموظفين |
| التقارير والرقابة | التقارير، أرشيف التقارير، سجل الهدر، الشكاوى |
| النظام | إعدادات المطعم، حساب المالك، خروج |

يجوز تحسين الأسماء القصيرة في العرض، لكن تبقى جميع روابط الوظائف ومساراتها القائمة متاحة. تظهر هذه المجموعات في شريط الوحدات العلوي أو قائمة وحدات منبثقة منه، لا في sidebar ثابت.

## قواعد المنع

- لا `dark:` في مكونات الويب المستهدفة ولا مفتاح تبديل سمة.
- لا `bg-gradient-*` أو `linear-gradient` أو `glass` أو `backdrop-filter`.
- لا `shadow-glow` أو `hover-lift` أو `hover-scale` أو مكوّنات `TiltCard`.
- لا chatbot أو assistant أو زر عائم أو sparkle icons أو «insights» مبهمة في واجهة المدير.
- لا عبارات تسويقية داخل الواجهة؛ التنبيه يذكر المشكلة والفعل، لا وعودًا مثل «كل شيء تحت السيطرة».
- لا تجعل البطاقة قابلة للنقر دون مؤشر واضح أو إجراء مذكور.
- لا تعِد استخدام شبكة KPI المنفصلة أو بانر تنزيل التطبيق أو المساحة البيضاء الواسعة كتركيب لصفحة المدير.
