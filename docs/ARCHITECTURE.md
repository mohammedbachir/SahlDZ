# خريطة الواجهة المعمارية — SahlDZ

## الحالة التقنية الحالية

- React 19 + TypeScript + Vite + TanStack Router/Start.
- Tailwind CSS v4 ورموز CSS في `src/styles.css`.
- TanStack file routes: المسارات المصدرية في `src/routes/` وملف المسارات المولد `src/routeTree.gen.ts` (لا يعدّل يدويًا).
- الواجهة المشتركة في `src/components/ui/`، والبيانات/الصلاحيات عبر `src/lib/` وSupabase.
- تقرير Graphify مطابق للـ commit الحالي `30484a2`، ويحدد `Button` و`Input` و`useRestaurantId()` و`tx()` كعناصر مشتركة مركزية.

## الحدود الوظيفية

| المنطقة | المسارات/الملفات الأساسية | القرار |
| --- | --- | --- |
| إدارة المدير | `src/routes/ops.tsx` و`src/routes/ops.*.tsx` و`src/components/ops-overview.tsx` | النطاق الأول والأهم |
| حساب المالك وإعداداته | `src/components/account-shell.tsx` و`src/routes/account/*` و`src/pages/settings-views/*` | داخل النطاق |
| لوحة ويب قديمة/موازية | `src/routes/dashboard.tsx` و`src/pages/{orders,menu,tables,analytics,accounting,reviews}.tsx` | توحّد بصريًا دون تغيير السلوك |
| التسويق | `src/routes/index.tsx` | مؤجل صراحة |
| تدفقات سطح المكتب/الميدان | `cashier*` و`kitchen*` و`waiter*` و`mobile*` و`t.$token.tsx` و`r.$token.tsx` | خارج النطاق |

## طبقات التغيير المسموح بها

1. `src/styles.css`: استبدال رموز التصميم العامة بواجهة Light-only وإزالة الأدوات الزخرفية غير المستخدمة تدريجيًا.
2. `src/components/ui/{button,card,input,table,badge,...}.tsx`: تثبيت عقود الشكل المشتركة مع الحفاظ على public props.
3. تخطيطات المدير: `ops.tsx` و`account-shell.tsx` ثم `dashboard.tsx` بحسب المسار.
4. الصفحات: تعديل البنية المرئية وclass names فقط، مع إبقاء hooks والاستعلامات وأنواع البيانات ومعالجات الأفعال كما هي.

## حدود إعادة الهيكلة المصرح بها

- يمكن تغيير ترتيب عناصر `NAV_ORDER` وتجميعها بصريًا في `src/routes/ops.tsx`، وتبسيط labels المعروضة، مع إبقاء `AREA_PATHS` ومسارات TanStack كما هي.
- يمكن فصل أو دمج أقسام العرض داخل `/ops` وصفحات الإدارة، وإعادة موضع الأفعال والفلاتر والتصدير في شريط أدوات موحّد.
- لا يعني تغيير الهيكل نقل منطق البيانات أو إعادة تسمية جداول قاعدة البيانات أو تغيير `OpsArea`/صلاحياتها.
- ملف `docs/RESULT.md` سجلّ ادعاءات التنفيذ السابق، وليس معيار قبول. لقطة الواجهة المتاحة أظهرت بقاء بانر التحميل وشبكة KPI وزر عائم؛ يجب التحقق من النتيجة بصريًا قبل أي ادعاء باكتمال المرحلة التالية.

## تفويض V4 التقني

- يعاد بناء JSX/CSS الخاصين بـ `OpsLayout` و`OpsOverview` من الصفر ضمن الملفات نفسها أو بمكوّنات عرض جديدة محلية واضحة؛ لا يقتصر العمل على class names.
- يجوز استبدال sidebar الحالي بتنقل علوي من صفين، مع الحفاظ على `Link` targets و`canViewArea` و`canWriteArea` و`requireOpsLayoutAccess` كما هي.
- يعاد ترتيب مناطق صفحة `/ops` بالكامل. يسمح بإعادة استخدام دوال تحميل البيانات فقط، ولا يعاد استخدام مصفوفة البطاقات أو القوالب المرئية السابقة.
- يطبق النمط الجديد على صفحات العمليات من خلال صفحات عمل كاملة، لا على شكل card wrappers حول البنية القديمة.

## ثوابت لا تمس

- `beforeLoad`، دوال الصلاحيات (`requireOpsAccess` و`requireOwner`) ومنطق الأدوار.
- جميع استعلامات Supabase، schema، server functions، وحسابات الإيراد والربح.
- أسماء المسارات والروابط، ووسوم `data-annotate` الخاصة بالجولات ما لم تُحدّث الجولات بعناية في نفس المهمة.
- شاشات kiosk/desktop وQR وتدفقات الطلب.

## ملاحظات تقنية ظاهرة قبل التنفيذ

- `src/styles.css` يحتوي حاليًا على `.dark` وglass/shadow glow/hover-lift؛ وهي متعارضة مع الاتجاه المعتمد.
- `src/components/ThemeToggle.tsx` ومكونه داخل `src/routes/dashboard.tsx` يفعّلان Dark Mode؛ يجب إزالتهما من واجهات الويب الجديدة بعد التأكد من عدم استعمالهما في تدفق خارج النطاق.
- `src/components/ops-overview.tsx` يعرض ست بطاقات KPI زجاجية؛ يعاد تنظيمه إلى شريط مالي أفقي، قائمة تنبيهات قابلة للفعل، ومحتوى سفلي مفيد دون تغيير طريقة جلب البيانات في المرحلة الأولى.
- `src/components/AdminChatBot.tsx` موجود في تخطيطات المدير؛ يخرج من واجهة المدير في نطاق إعادة التصميم لأنه يتعارض مع قرار عدم استخدام عناصر AI. لا تحذف منطق المكوّن من تدفقات خارج النطاق.
- هناك تغييرات غير متعلقة بهذه المبادرة في شجرة العمل؛ لا يجب تعديلها أو عكسها.
