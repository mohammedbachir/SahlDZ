# تقرير مشاكل الموقع

## نطاق المراجعة

هذا التقرير مبني على مراجعة ثابتة للكود وملفات الإعداد الحالية، وليس اختباراً كاملاً أثناء التشغيل في المتصفح أو على بيئة Firebase الإنتاجية. تم توثيق المشاكل التي لها دليل مباشر في الكود، مع ذكر الأثر واتجاه المعالجة المقترح.

## مشاكل حرجة وعالية الأولوية

### 1. أمر الإنتاج يستدعي ملفاً غير موجود

> **ملاحظة المعالجة:** حُذف `node scripts/build-vercel.mjs` من أمر البناء في `package.json`، فأصبح `build` هو `vite build`. ينجح `npm run build` الآن.

- **الدليل:** `package.json:11` يشغّل `vite build && node scripts/build-vercel.mjs`، ولا يوجد مجلد `scripts/` أو الملف `scripts/build-vercel.mjs` في المستودع.
- **الأثر:** قد ينجح بناء Vite ثم يفشل أمر `npm run build` مباشرة عند تشغيل Node، مما يمنع النشر الآلي.
- **المعالجة:** إضافة سكربت التغليف المطلوب أو تعديل أمر البناء ليتوافق مع طريقة النشر الفعلية، ثم اختبار `npm run build` في بيئة نظيفة.

### 2. مسار إنشاء المطعم غير منفذ

- **الدليل:** `src/lib/auth.ts:6-24` يوجه المستخدم الذي لا يملك مطعماً إلى `/setup`، بينما `src/routes/setup.tsx:10-28` يعرض رسالة تفيد بأن صفحة الإعداد غير مرفوعة ويحتوي فقط على رابط إلى لوحة التحكم.
- **الأثر:** المستخدم الجديد لا يستطيع إنشاء مطعمه أو إكمال التسجيل بشكل صحيح، وقد يصل إلى لوحة تحكم بلا بيانات حقيقية.
- **المعالجة:** تنفيذ نموذج إنشاء المطعم وربطه بالمستخدم الحالي، ثم إعادة التوجيه إلى لوحة التحكم بعد نجاح العملية. يجب منع الوصول إلى لوحة التحكم الحقيقية قبل اكتمال الإعداد.

### 3. استعادة كلمة المرور غير متاحة

- **الدليل:** `src/routes/forgot-password.tsx:10-28` لا يحتوي على حقل بريد أو استدعاء لخدمة استعادة كلمة المرور؛ يعرض رسالة placeholder ورابط العودة فقط.
- **الأثر:** رابط «نسيت كلمة المرور؟» في `src/routes/login.tsx:148-152` يقود إلى مسار لا ينفذ الاستعادة، مما قد يمنع المستخدمين من استرجاع حساباتهم.
- **المعالجة:** إضافة نموذج بريد، واستدعاء `auth.resetPasswordForEmail` أو ما يعادله في Firebase، وإنشاء مسار آمن لتعيين كلمة مرور جديدة.

### 4. وظائف خادم كثيرة هي واجهات وهمية ولا تحفظ البيانات

- **الأدلة:**
  - `src/lib/settings.functions.ts:3-68` يعيد قيماً ثابتة ولا ينفذ تحديثات الإعدادات أو حسابات الموظفين.
  - `src/lib/telegram.functions.ts:3-32` يعيد `enabled: false` و`ok: true` دون ربط Telegram فعلياً.
  - `src/lib/daily-summary.functions.ts:3-14` يعيد ملخصاً معطلاً ولا يرسل شيئاً.
  - `src/lib/summary-bot.functions.ts:3-35` يعيد حالات فارغة وثوابت نجاح.
  - `src/lib/ops-alerts.functions.ts:3-10` يعيد `sent: false` دون إرسال التنبيهات.
- **الأثر:** واجهة الإعدادات قد توحي للمستخدم بأن الحفظ أو الربط أو الإرسال نجح، بينما لا يحدث تغيير دائم أو إجراء خارجي.
- **المعالجة:** تنفيذ التحقق من الجلسة والمطعم والملكية على الخادم، ثم ربط كل وظيفة بعمليات Firebase فعلية وإرجاع أخطاء صريحة عند الفشل. يجب ألا تعاد حالة نجاح ثابتة لعملية لم تُنفذ.

### 5. تحديد محاولات تسجيل الدخول قابل للتجاوز

- **الدليل:** `src/lib/rate-limiter.ts:11-24` يخزن العدادات في `window.localStorage`، وتستخدمه صفحات `src/routes/login.tsx:38-42` و`src/routes/signup.tsx:61-65`.
- **الأثر:** يمكن للمستخدم حذف بيانات المتصفح أو تغييرها أو استخدام متصفح/جهاز آخر لتجاوز الحماية. لذلك لا يوفر هذا حماية حقيقية من التخمين أو الهجمات الموزعة.
- **المعالجة:** نقل rate limiting إلى الخادم أو مزود المصادقة، مع اعتماد مفتاح يجمع بين الحساب وعنوان الشبكة/الجلسة وفق سياسة الخصوصية، وإبقاء المحدد المحلي كتحسين لتجربة المستخدم فقط لا كحد أمني.

## مشاكل متوسطة

### 6. محاكي Firebase لا يطابق دلالات الاستعلام الفعلية

- **الدليل:** `src/integrations/firebase/client.ts:37-96` ينشئ Stub يعيد نتائج فارغة أو نجاحاً دون تنفيذ، كما أن `like` و`ilike` في `src/integrations/firebase/client.ts:134-140` يحولان إلى عامل `>=`، وهو ليس بحثاً نصياً.
- **الأثر:** قد تعمل صفحات المعاينة ظاهرياً، لكن النتائج تختلف عن الإنتاج، وقد تظهر بيانات خاطئة عند استخدام البحث أو تعتمد الواجهة على نجاح وهمي.
- **المعالجة:** تعريف طبقة بيانات typed بعمليات واضحة بدلاً من Proxy عام، وكتابة اختبارات تكامل للاستعلامات المدعومة، وإرجاع خطأ صريح للعمليات غير المدعومة بدلاً من نتيجة فارغة.

### 7. التطبيق يستخدم توافقاً شكلياً مع Supabase وليس Firebase أصلياً بالكامل

- **الدليل:** `src/integrations/supabase/client.ts:1-3` يعيد تصدير عميل Firebase تحت اسم `supabase`، بينما تستخدم بقية الواجهة API بأسلوب Supabase مثل `supabase.from()` و`supabase.auth`.
- **الأثر:** قد يوحي اسم العميل بأن التطبيق متصل بـ Supabase، بينما السلوك الفعلي يعتمد على محول مخصص بين الواجهتين. أي عملية غير مدعومة في المحول قد تفشل بصمت أو تختلف عن سلوك Supabase المتوقع.
- **المعالجة:** توثيق أن Firebase هو Backend الفعلي، ثم استبدال اسم التوافق تدريجياً بعميل Firebase أو repositories typed واضحة، أو اعتماد Supabase فعلياً بدلاً من إبقاء طبقتين مختلطتين.

### 8. استخدام `any` واسع في طبقة البيانات يخفي أخطاء وقت الترجمة

- **الدليل:** `src/integrations/firebase/client.ts:37-529` يعلن السلاسل والعميل بنتائج `any`، مع تحويلات `as any` كثيرة.
- **الأثر:** يمكن تمرير حقول أو عمليات غير صحيحة دون أن يكتشفها TypeScript، خصوصاً في عمليات الحسابات والطلبات والصلاحيات.
- **المعالجة:** تحديد أنواع للعميل المتوافق مع Supabase، وواجهات نتائج موحدة، وأنواع لكل مجموعة بيانات، ثم تقليل التحويلات غير الآمنة تدريجياً.

### 9. OAuth غير منفذ فعلياً في محول Firebase

> **ملاحظة القرار:** أُزيل تسجيل الدخول الاجتماعي (Google وApple) بالكامل من التطبيق، وبقي تسجيل الدخول بالبريد وكلمة المرور فقط. البند يعتبر مغلقاً.

- **الدليل:** `src/integrations/firebase/client.ts:483-485` يعرّف `signInWithOAuth` كدالة تعيد `{ data: {}, error: null }` دون فتح مزود OAuth أو إنشاء جلسة.
- **الأثر:** أزرار Google وApple في `src/routes/login.tsx:65-95` و`src/routes/signup.tsx:96-127` قد تعرض نجاحاً ظاهرياً دون تسجيل دخول فعلي، حتى لو كانت إعدادات المزود صحيحة.
- **المعالجة:** تنفيذ OAuth باستخدام Firebase providers و`signInWithPopup` أو `signInWithRedirect`، ثم توحيد نتيجة الجلسة مع بقية adapter وتسجيل redirect domains في Firebase.

### 10. Realtime غير منفذ فعلياً

- **الدليل:** `src/integrations/firebase/client.ts:511-526` يعيد `channel()` و`subscribe()` و`unsubscribe()` كدوال فارغة تقريباً، مع حالة `SUBSCRIBED` ثابتة.
- **الأثر:** أي شاشة تعتمد على الاشتراكات اللحظية لن تحصل على تحديثات فعلية، وقد تعرض حالة قديمة حتى تتم إعادة تحميل الصفحة.
- **المعالجة:** استخدام Firestore `onSnapshot` داخل طبقة اشتراك typed، أو إزالة واجهة Realtime من الشاشات التي لا تدعمها فعلياً وإضافة polling صريح عند الحاجة.

### 11. وظائف الأدوار والتوصيل والاستلام لا تزال جزئياً placeholders

- **الدليل:** توجد معالجات `createServerFn` ثابتة أو غير مربوطة بقاعدة البيانات في `src/lib/waiter.functions.ts:49-63`، و`src/lib/cashier.functions.ts:78-83`، و`src/lib/individual-chef.functions.ts:46-62`، إضافة إلى وظائف `src/lib/delivery.functions.ts` و`src/lib/takeaway.functions.ts`.
- **الأثر:** قد تظهر شاشات النادل والكاشير والطاهي والتوصيل كأنها تعمل، لكن بعض القوائم أو عمليات التفعيل والتعديل لا تحفظ البيانات أو تعيد نتائج فارغة دائماً.
- **المعالجة:** مراجعة كل server function مقابل عملية Firebase فعلية، إضافة تحقق الجلسة والدور والمطعم، وعدم إبقاء placeholders في مسارات الإنتاج.

### 12. المستخدم المصادق بلا مطعم قد يرى بيانات المعاينة

### 8. المستخدم المصادق بلا مطعم قد يرى بيانات المعاينة

- **الدليل:** بعد فشل العثور على مطعم أو دور موظف، يستخدم `src/routes/dashboard.tsx:201-212` `localStorage` ثم يضع المطعم الوهمي `مطعم السهل` و`mock-restaurant-id`.
- **الأثر:** يمكن أن تظهر للمستخدم المصادق شاشة تجريبية بدلاً من مسار الإعداد، ما يسبب التباساً وقد يؤدي إلى تنفيذ عمليات وهو يعتقد أنها على مطعمه الحقيقي.
- **المعالجة:** قصر fallback الوهمي على جلسات المعاينة غير المصادق عليها. المستخدم المصادق بلا مطعم يجب أن يعاد إلى `/setup` مع حالة واضحة.

### 9. دعم اللغات غير مكتمل

- **الدليل:** `src/lib/i18n.ts:99-106` يعلن `ar`, `fr`, و`en` ضمن `supportedLngs`، لكن المورد المسجل فعلياً هو `ar` فقط. كما توجد نصوص عربية مباشرة في `src/routes/login.tsx:29-40` و`src/routes/setup.tsx:15-18` وغيرها.
- **الأثر:** اختيار الفرنسية أو الإنجليزية قد يعرض مفاتيح أو fallback عربي، وتبقى أجزاء من الواجهة غير قابلة للترجمة.
- **المعالجة:** إما توفير موارد كاملة للغات المعلنة، أو إزالة اللغات غير الجاهزة من قائمة الدعم، ونقل النصوص المباشرة إلى ملفات الترجمة.

### 10. نقاط OAuth تشير إلى مسار callback غير موجود ضمن المسارات الحالية

> **ملاحظة القرار:** أُزيل تسجيل الدخول الاجتماعي (Google وApple) بالكامل، فلا توجد نقاط OAuth ولا مسار callback مطلوب. البند يعتبر مغلقاً.

- **الدليل:** `src/routes/login.tsx:69-72` و`src/routes/login.tsx:85-88` و`src/routes/signup.tsx:101-104` تستخدم `/auth/callback`، بينما لا يظهر مسار `src/routes/auth.callback.tsx` ضمن شجرة المسارات الحالية.
- **الأثر:** قد يعود المستخدم من Google أو Apple إلى مسار غير معالج، أو لا تكتمل عملية الجلسة وإعادة التوجيه.
- **المعالجة:** إضافة route callback يعالج جلسة OAuth أو استخدام آلية callback المدعومة مباشرة من محول Firebase، ثم اختبار التدفق على بيئة منشورة وليس localhost فقط.

## وظائف ناقصة أو مشاكل تجربة واضحة

### 11. رموز وضع المعاينة ثابتة ويمكن توقعها

- **الدليل:** `src/routes/waiter-login.tsx:133-137` يستخدم `mock_waiter`، و`src/routes/kitchen-login.tsx:146-150` يستخدم `mock_chef`، و`src/routes/cashier-login.tsx:65-68` يستخدم `mock_cashier`.
- **الأثر:** هذه الرموز مناسبة للعرض التجريبي فقط، لكنها خطرة إذا قبلتها أي نقطة نهاية كاعتماد حقيقي أو إذا اختلطت بيانات المعاينة ببيانات الإنتاج.
- **المعالجة:** إبقاء هذه الرموز محلية في preview فقط، ووضع تحقق خادمي يمنعها في بيئة الإنتاج، مع فصل واضح بين بيانات demo والبيانات الحقيقية.

### 12. الإعدادات والربط الخارجيان يعرضان نجاحاً غير حقيقي

- **الدليل:** صفحة الإعدادات تستدعي وظائف مثل `setRestaurantBotToken` و`setSummaryBotToken`، لكن المعالجات في `src/lib/telegram.functions.ts:25-32` و`src/lib/summary-bot.functions.ts:15-35` تعيد نجاحاً ثابتاً دون حفظ الرمز أو التحقق منه.
- **الأثر:** المستخدم قد يظن أن Telegram أو الملخصات اليومية مفعلة، بينما حالة النظام تبقى غير مفعلة بعد إعادة التحميل.
- **المعالجة:** عرض حالة pending/error/success مبنية على نتيجة فعلية، وتخزين الرموز في مكان خادمي آمن وعدم إعادتها إلى المتصفح إلا عند الضرورة.

## ترتيب الإصلاح المقترح

1. إصلاح بناء الإنتاج والتحقق من `npm run build`.
2. تنفيذ إنشاء المطعم واستعادة كلمة المرور (أُزيل تسجيل الدخول الاجتماعي بالكامل).
3. استبدال وظائف الخادم الوهمية بعمليات فعلية مع صلاحيات وتحقق من الملكية.
4. نقل حماية تسجيل الدخول إلى الخادم وتحسين طبقة Firebase typed.
5. منع fallback المعاينة للمستخدمين المصادق عليهم، ثم استكمال الترجمة وفصل preview عن production.

## تحقق لاحق مطلوب

- تشغيل `npm run build` في بيئة نظيفة.
- اختبار التسجيل وتسجيل الدخول بالبريد وكلمة المرور، واستعادة كلمة المرور، وإنشاء المطعم.
- اختبار حفظ الإعدادات والموظفين وTelegram والملخصات بعد إعادة تحميل الصفحة.
- اختبار صلاحيات أدوار العمليات على مطاعم مختلفة.
- اختبار مسارات المعاينة مع التأكد من عدم قبول رموز `mock_*` في الإنتاج.
